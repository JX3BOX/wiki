# Wiki 多语言维护约定

## 支持语言

Wiki 当前支持：

- `zh-CN`：简体中文。
- `zh-TW`：台湾繁体中文。
- `en-US`：英文。
- `vi`：越南文。

四套语言包必须保持相同的键集合、非空字符串和插值参数。新增、删除或重命名 key 时必须同时更新四套语言。

## 简中文案等价

把硬编码提取到 i18n 不代表可以顺便改写中文。简中展示必须逐字保留原页面的措辞、标点和必要空格。

通用 key 与原场景文案不一致时，应增加场景专用 key，而不是让多个页面共用一个近似文案。本轮专用 key 主要位于：

- `ui.achievement.mobile`
- `ui.quest.mobile`
- `ui.knowledge.mobile`

例如“设为已完成”和“设为完成”、“确认”和“确定”、“任务起点：”和“任务起点:”均不是可直接互换的文本。

## 台湾繁体

`zh-TW` 固定采用台湾用语，不使用香港繁体用语。

简中逐字转换只作为新增 key 的兜底；一对多词义和地区用语必须按完整 key 显式覆盖，例如：

- 搜索 → 搜尋
- 数据 → 資料
- 加载 → 載入
- 服务器 → 伺服器
- 保存 → 儲存
- 一口价 → 直購價

各百科入口的繁体标题、关键词和描述应分别维护，不能用同一份机械 SEO 文案覆盖所有业务。

## 路由 Head

`src/router/i18n-head.js` 统一从 `pages.common` 读取：

- `appendTitle`
- `fallbackTitle`
- `fallbackKeywords`
- `fallbackDescription`

`zh-CN` 的以上值必须与 `src/settings.js` 逐字一致，确保首屏、未知路由和缺少翻译时的线上回退行为不变。其他语言可以使用本地化标题、关键词、描述和后缀。

## 用户可见硬编码

成就、任务和通识移动端组件中的用户可见中文应进入语言包。以下内容可以保留，但必须按文件和原文字面精确加入 allowlist：

- 接口协议值和服务端固定枚举。
- 游戏固有数据。
- 字体名称。
- 开发日志。

CSS `content` 中的中文原则上禁止；目前只允许物品方案中两处为保持线上兼容而保留的“主”徽标，详见 [物品百科业务约定](./item.md)。

## 验证

`tests/i18n.test.js` 负责检查：

- 四套语言的 key、非空值和插值参数一致。
- 源码静态引用的 `ui/pages` key 全部存在。
- 移动端中文硬编码与 allowlist。
- CSS 伪元素中文 allowlist。
- 台湾繁体的乱码、简体字和大陆用语。
- 路由 head fallback 契约。

`tests/item-price-i18n.test.js` 负责检查物品价格单位和简中算法等价。

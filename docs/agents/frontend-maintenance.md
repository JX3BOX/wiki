# Wiki 前端维护与功能等价约束

## 适用范围

本文记录 Wiki 的跨业务前端维护边界，适用于成就、物品、任务和通识四个入口。

代码整理、样式优化、i18n 补全和构建优化都必须以已部署版本的用户行为为基线。本轮核对基线为 2026-09-04 的 `origin/master`（`fa75e071`）。后续维护应以当时实际部署的版本为准，不应自行回退到更早提交。

## 功能不变量

未获得明确业务需求时，下列行为不得在代码或样式优化中改变：

- 路由表及 App、小程序分支。
- service API、请求参数、请求时序和缓存策略。
- 分页边界、游标推进和搜索触发方式。
- store 状态类型、空值约定和本地存储键。
- 按钮的可用状态、加载状态、点击结果和提示时机。
- 链接地址、打开方式以及 `rel`、referrer 行为。
- 业务模块的显隐条件、加载态和失败态。

允许整理 import、拆分纯函数、补充翻译和调整纯视觉样式，但简中最终文案、DOM 条件、事件绑定和请求结果必须保持等价。成就关联面板的失败态静默规则是经业务确认的例外，详见 [成就百科业务约定](./cj.md)。

## 公共组件与按需注册

`src/utils/bootstrap.js` 只从 JX3BOX UI 的 i18n 子入口加载语言能力，并显式保留 `i18nMixin`。页面实际使用的公共组件必须在所属组件中局部引入和注册，当前覆盖包括：

- 布局组件：`CommonHeader`、`Breadcrumb`、`Footer`、`LeftSidebar`、`Main`、`RightSidebar`。
- 侧栏组件：`RightSideMsg`。
- 详情页打赏组件：`Thx`。
- 各业务直接使用的评论、价格、二维码和悬浮操作组件。

新增 JX3BOX UI 组件时，应继续使用明确的子路径 import 和局部注册，不要依赖包根入口重新全量安装。多入口共享组件的 import 顺序应保持一致，避免 CSS 拆包后的加载顺序漂移。

按需注册必须检查可达的第三方子组件，而不能只扫描本仓库模板。例如 `WikiPanel` 可打开 `DesignTask`，后者使用 `el-rate`，所以全局 Element Plus installer 必须保留 `ElRate`。

## 代码与样式约束

- Lodash 仅从函数子路径引入，例如 `lodash/get`、`lodash/pick`、`lodash/chunk`，不得恢复根入口导入。
- 纯函数重构必须保留旧输入的类型转换、边界值和返回格式。
- CSS 命名继续遵循 [前端 CSS 命名规范](../AGENTS.md)。
- 为 i18n 改造 CSS 伪元素文案前，必须确认真实 DOM、属性透传和多语言尺寸均可靠；不能以标签消失或溢出为代价清理硬编码。

## 本轮明确撤回的方案

以下方案会改变线上功能或体验，不属于最终改动，后续不要按“既定优化”重新实现：

- 修改请求竞态、分页、错误兜底、按钮禁用或加载策略。
- 恢复旧版 App、小程序独立路由或专用样式入口。
- 改变成就角色状态的空值类型。
- 新增 HTML 清洗指令或改变外链 referrer 行为。
- 删除旧移动端、兼容组件或历史路由文件。
- 将默认展示的物品价格图改成异步 chunk。
- 删除可达公共组件依赖的 `ElRate`。
- 用不可靠的 `data-*` 属性透传替换“主”徽标文案。

## 验证要求

跨业务优化完成后至少执行：

```bash
npm test
npm run lint
npm run build
npm run check:bundle
git diff --check
```

同时应对涉及页面做最小范围冒烟测试，重点检查模块显隐、公共组件解析和控制台运行时错误。
